# The PostgreSQL driver lives in requirements.txt, because production runs on
# PostgreSQL. The CI job that runs the whole suite against a real server gets it
# from there. SQLite accepts things PostgreSQL rejects - a NUL byte in a text
# column was found exactly this way - so a suite that has only run on SQLite is
# evidence about SQLite.

# pip-tools, which compiles the two lock files, is deliberately NOT listed
# here. It depends on pip and setuptools themselves, so a lock generated with it
# in the set pins pip inside a file that pip is being asked to install — which
# needs --allow-unsafe and installs a pip over the running one. Install it into
# a throwaway environment when the locks need regenerating; the command is in
# requirements.lock.
